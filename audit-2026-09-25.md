# AMY Electric — Website Audit

**Date:** 2026-09-25
**Scope:** 311 HTML pages (242 root, 64 blog, 5 case-studies) · live production at `https://amyelectric.com`
**Method:** full local static analysis + live HTTP verification of every broken link + Lighthouse (mobile) against production

---

## Verdict

The foundation is genuinely strong — flawless metadata coverage, 100% valid structured data, zero broken canonicals, zero image-alt or CLS defects, and correct 301s. Lighthouse SEO is **100** and accessibility is **100** on the homepage.

The problems are concentrated in **one broken template** that covers 59 city pages (19% of the site), and in **structured data that has drifted out of sync with visible content**. Both are cheap to fix and high-impact.

---

## CRITICAL

### 1. Primary call-to-action 404s on 59 city pages

`/contact` does not exist anywhere in the repo. Three separate CTAs on each of 59 city pages point at it:

| Location | Markup | Result |
|---|---|---|
| Primary nav button | `<a href="/contact" class="nav-cta">Free Estimate</a>` | **404** |
| Main conversion CTA | `<a href="/contact" class="btn btn-navy">Get Free Estimate</a>` | **404** |
| Footer | `<a href="/contact">Contact Form</a>` | **404** |

- **118 broken link instances** (59 nav + 59 CTA), plus 59 footer = 177.
- Affected: every "neighborhood" city page — `city-arleta`, `city-atwater-village`, `city-beverly-grove`, `city-chinatown`, `city-koreatown`, `city-los-feliz`, `city-silver-lake`, `city-verdugo-city`, `city-westmont`, and 49 more.
- Working targets already exist: `/#estimate` returns 200 and `id="estimate"` is on the homepage. `tel:18183025614` is what the 183 healthy pages use in the same slot.
- Corroborating evidence of intent: `worker.js:556` still maps `'/contact.html': '/markdown/contact.md'` — a contact page was planned and never built.

**Fix:** `href="/contact"` → `href="/#estimate"` (or `tel:18183025614` in the nav slot, matching the working template).

### 2. A 404 URL is baked into navigation *and* BreadcrumbList schema

`/areas-served` also does not exist. The real page is `/service-areas` (200 OK). On the same 59 pages:

```html
<a href="/areas-served" class="active">Service Areas</a>          <!-- nav -->
<a href="/">Home</a> › <a href="/areas-served">Service Areas</a>  <!-- visible breadcrumb -->
```
```json
{"@type":"ListItem","position":2,"name":"Service Areas",
 "item":"https://amyelectric.com/areas-served"}                    <!-- BreadcrumbList -->
```

- **236 broken instances** across those 59 pages (4 per page: nav, visible breadcrumb, and two more), plus 59 in the JSON-LD.
- **0 pages** link to the correct `/service-areas`; **59** link to the 404.
- Google is being explicitly told the breadcrumb parent for 59 pages is a 404 URL.
- The `class="active"` on a dead link means the nav highlights the broken item as if it were current.

**Fix:** `/areas-served` → `/service-areas` in HTML **and** in the JSON-LD.

## HIGH

### 3. 184 "phantom" FAQ questions — schema content that isn't on the page

FAQPage `mainEntity` declares questions with no visible counterpart on **53 pages**. This violates Google's structured-data policy and can invalidate the FAQ rich result entirely.

Verified example — `city-beverly-hills.html` shows 8 FAQs but declares 9. Three declared questions appear nowhere in the rendered body:
- "what electrical services do you provide in Beverly Hills"
- "how quickly can you respond in Beverly Hills"
- "are you licensed to work in Beverly Hills" *(page actually says "…licensed **and insured**…")*

Also `200-amp-panel-upgrade.html` declares "Can I keep my existing breakers?" — the string exists in that file **only inside the JSON-LD block**.

Worst offenders: `blog/gfci-afci-protection-la.html` (7/7 phantom), `federal-pacific-zinsco-panel-replacement.html` (6/6), `blog/ladwp-e-permit-guide.html` (6/7). Every one of the 16 "premium" city pages (Beverly Hills, Burbank, Glendale, Pasadena, Santa Monica, Encino…) carries 4 phantom questions from the same template.

### 4. Render-blocking Google Fonts `@import` that the site's own CSP blocks

`css/style.min.css` line 1 — and its source, `css/src/00-design-tokens.css:2`:

```css
@import url('https://fonts.googleapis.com/css2?family=Roboto:wght@400;500;700&display=swap');
```

Three compounding problems:
1. **It can never load.** The site sets `style-src 'self' 'unsafe-inline'` in `_headers`, so every page logs a CSP violation. Lighthouse flags it under `errors-in-console` and `inspector-issues`.
2. **An `@import` at the top of the main stylesheet is render-blocking** — CSS must download, *then* resolve the import. This delays LCP on all 311 pages.
3. **Roboto is never used.** `font-family` in the built CSS resolves only to `'Barlow Condensed'`, `'Source Serif 4'`, `var(--cond)`, `var(--serif)`. `--font-family-base` (line 20 of the token file) is defined and never referenced. `Roboto` appears exactly once in 30KB of CSS — in the import itself.

**Fix:** delete the `@import` line, rebuild with `python3 scripts/build-css.py`. Pure win, one line, no visual change.

### 5. Three empty blog stubs, `noindex` but still in the sitemap

| Page | Visible words | Title |
|---|---|---|
| `blog/smart-home-electrical-upgrades-la.html` | **33** | Smart Home Electrical Upgrades in Los Angeles \| AMY |
| `blog/how-to-choose-electrician-los-angeles.html` | **37** | How to Choose an Electrician in Los Angeles \| AMY Electric |
| `blog/signs-you-need-electrical-panel-upgrade.html` | **39** | 8 Signs You Need a Panel Upgrade \| Los Angeles \| AMY |

Each is a 5.7KB file whose H1 is a verbatim copy of its own `<title>`, with no body. All three are `noindex` **and** present in `sitemap.xml` — a direct robots/sitemap conflict. Each also duplicates a real, indexed post (`blog/smart-home-electrical-upgrades.html`, `blog/choosing-electrician-la.html`).

**Fix:** delete them and 301 to the real equivalents, or write the content and drop the `noindex`.

### 12. Accessibility regressions on the 59-page template

Homepage scores 100; `city-arleta` scores 93:
- `heading-order` — footer jumps to `<h4>` in `div.footer-links`
- `aria-hidden-focus` — `div.sticky-call` is `aria-hidden="true"` but contains a focusable phone link. The phone link is invisible to screen readers on every one of the 59 pages.

## Two findings retracted after investigation

- **"Trim unused font preloads"** — wrong. All five woff2 files are used above the fold; the italic
  serif renders inside `<h1>` on 94 pages (`<h1>Electrician in <em>Arleta</em>, CA</h1>`).
  `font-display: optional` is already set on every `@font-face`. **No change made** — trimming them
  would have risked FOUT for no gain.
- **"6 sitemap URLs are redirects"** — wrong. The sitemap already used the canonical trailing-slash
  form. The real (smaller) issue was 59 pages linking to `/blog`, which 307-redirects; that is fixed.

## Left alone deliberately

- **63 self-links** across 47 pages — these are nav items pointing at the current page, a normal
  pattern the JS relies on for `.active` styling. Removing them risks visual regressions sitewide for
  negligible crawl benefit.
- **189 unmarked visible questions** — these are editorial section headings phrased as questions
  ("What Is an Electrical Panel Upgrade?", "Ready for a Modern, Safe Panel?"), not FAQ disclosures.
  Marking them up would be schema abuse. **Opportunity, not a defect:** writing real `<details>` FAQ
  sections for the 17 pages that had fabricated schema would recover those rich results legitimately.
- **`seo-audit-report.html`** — internal report, but `noindex` and unlinked, so harmless.
- **5 blog pages missing `</head>`** — pre-existing in git HEAD, untouched by this work.
