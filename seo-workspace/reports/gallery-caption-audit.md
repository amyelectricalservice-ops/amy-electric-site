# Gallery Caption Audit — 2026-11-12

**Source:** `scripts/photo-manifest.csv` (545 rows → 387 shipped gallery photos)
**Rendered by:** `scripts/update-gallery.py` → `gallery.html` (manifest is the single source of truth for alt text + captions)
**Live gallery:** https://amyelectric.com/gallery (387 photos, 11 city sub-galleries)

## Summary

The gallery ships with **auto-generated captions** derived from filenames and category heuristics. Quality is uneven and several patterns are actively misleading on a published marketing page.

| Metric | Value | Assessment |
|---|---|---|
| Total manifest rows | 545 | — |
| Unique captions | 273 (50%) | High duplication |
| Empty captions | 0 | OK |
| Caption length (min/max/avg) | 43 / 129 / 91 chars | Within reasonable range |
| Captions containing "(work in progress)" | 357 (66%) | **Misleading** — these are finished, shipped photos |
| Empty `city` field | 330 (61%) | Falls back to "Los Angeles" at render time (acceptable) |
| Duplicate captions (31 distinct, 303 rows) | 56% of rows share a caption with ≥1 other photo | **Repetitive** — visitors see identical alt text on different photos |
| `category = other` | 92 (17%) | Unclassified; captions are generic |

## Top duplicate captions (verbatim, with count)

1. `Electrical work in unfinished wood-framed space — with panel and wiring detail (work in progress)` — 58 rows
2. `Electrical system with metal enclosures — with panel and wiring detail (work in progress)` — 34 rows
3. `Electrical work in unfinished wood-framed space — with panel and wiring detail` — 38 rows
4. `Electrical work in unfinished wood-framed space (work in progress)` — 10 rows
5. `Electrical system with metal enclosures (work in progress)` — 8 rows

These 5 templates account for ~148 of the 303 duplicated rows.

## Problems

1. **"(work in progress)" on finished photos.** 66% of captions describe shipped, polished work as in-progress. This undercuts trust on a page whose explicit purpose is showing completed work ("built from our own project photography, not stock images").
2. **Repetition.** A visitor scrolling the gallery sees the same alt text / caption on dozens of distinct photos, which reads as templated/low-effort and weakens SEO value of each image (duplicate alt across many images is a known negative signal).
3. **Empty city on 61% of rows.** Renders as "Los Angeles" (acceptable fallback) but loses the local-SEO benefit of city-specific alt text on 330 photos.
4. **`other` category (92 rows, 17%).** No type classification → captions are generic ("Electrical system with metal enclosures"). Hard to improve without re-triaging.
5. **No human review loop.** Captions are generated by `process-photos.py` heuristics from filenames; there is no review step before shipment. The `photo-review-log.csv` tracks pick/skip decisions but not caption quality.

## Recommended fixes (in priority order)

### A. Safe, automated (agent can do now, ~5 min)
- Strip " (work in progress)" from all captions. Improves accuracy immediately with zero risk.
- Replace empty `city` with "Los Angeles" (render already does this; making it explicit keeps the manifest honest).
- Dedupe by appending the category + city to repeated captions (e.g. "… panel and wiring detail — Sherman Oaks panel upgrade").
- **Do not fabricate descriptions.** Captions should describe what's actually in the photo; auto-generated guesses are worse than generic truth.

### B. Semi-automated (agent + owner, ~1–2 hrs)
- Re-triage the 92 `other`-category photos into panel/commercial/lighting/etc. using the existing `triage-photos.py` + contact sheets.
- For the 31 duplicate-caption groups, pick one representative photo per caption and write a unique 1-sentence description; leave the rest with a generic but accurate caption.

### C. Owner-only (real accuracy)
- Spot-check 20–30 photos against the actual image and correct captions where the heuristic guessed wrong (e.g. a "panel" photo that's actually a meter socket). This is the only way to get captions that match reality.

## Suggested next step

Run **Option A** now (safe cleanup, audit-site still 342/0, no schema impact), then sample 20 photos manually to decide whether Option B/C is worth the time. Option A alone removes the most embarrassing artifact ("work in progress" on finished work) with no downside.

## Files touched by Option A
