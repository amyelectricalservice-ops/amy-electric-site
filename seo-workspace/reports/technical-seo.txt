2. HTTPS + REDIRECTS
================================================================================

2.1 HTTP → HTTPS Redirect
  Test: curl -sI http://amyelectric.com/
  Result: HTTP/1.1 200 OK (not a redirect!)
  STATUS: FAIL

  The HTTP version of the site returns content directly without redirecting to HTTPS.
  Cloudflare's "Always Use HTTPS" setting (referenced in _redirects file comments) 
  does not appear to be enabled. Users and search engines accessing http:// will 
  not be redirected to the secure version.

2.2 www → non-www Redirect
  Test: curl -sv https://www.amyelectric.com/
  Result: "Could not resolve host: www.amyelectric.com" (DNS NXDOMAIN)
  STATUS: FAIL

  The www subdomain does not resolve at all. nslookup confirms NXDOMAIN.
  The _redirects file mentions a Cloudflare Bulk Redirect rule, but it cannot work
  if www.amyelectric.com has no DNS A/AAAA/CNAME record.

2.3 _redirects File
  Path: /home/amram/WEBSITE/_redirects
  Content: Comments only (no actual redirect rules)
    - States HTTPS enforcement is handled in Cloudflare dashboard
    - States www→non-www is handled via Cloudflare Bulk Redirect
  
  ASSESSMENT: FAIL
  - No actual redirect rules in the file.
  - The Cloudflare dashboard settings referenced are either not configured or 
    misconfigured (evidenced by HTTP serving content directly).

  og:url:     <meta property="og:url" content="https://amyelectric.com/ev-charger-installation.html">
  ASSESSMENT: WARNING - Canonical points to .html URL, but the .html URL issues a 307

  Location-service: https://amyelectric.com/ev-charger-installation-los-angeles (clean)
  Emergency:    https://amyelectric.com/emergency-electrician    (clean)

  All canonical tags and og:url values point to .html versions, while the actual
  content is served at clean URLs without .html extension.

  The site uses Cloudflare redirect rules to convert .html → clean URLs via 307
  (temporary) redirects. These should be 301 (permanent) redirects if this is the
  intended final URL structure.

  ASSESSMENT: WARNING - Clean URLs are the preferred format, but:
  - Redirects are 307 (temporary), should be 301 (permanent)
  - Canonical tags point back to .html versions (conflict)
  - Sitemap lists .html URLs (should be clean URLs)
  - Internal links use .html URLs (should be clean URLs)

     in Cloudflare dashboard SSL/TLS settings.
  2. www.amyelectric.com DNS does not resolve (NXDOMAIN). Add a DNS record for
     the www subdomain (CNAME to amyelectric.com or A/AAAA record).

HIGH (should fix):

     They only have FAQPage. This is a significant local SEO gap. Each city page
     should have an Electrician schema with areaServed containing the city name,
     postal codes, and defined region.
  4. Canonical/redirect mismatch: All pages have canonical tags pointing to .html
     URLs, but .html URLs 307 redirect to clean URLs. Correct approach:
     - Update canonical tags to point to clean URLs (no .html extension), OR
     - Change redirect to 301 (permanent) and update sitemap to use clean URLs.
  5. 307 redirects should be 301 (permanent) since clean URLs are the intended
     final URLs.

MEDIUM (fix when convenient):
  6. Sitemap lists .html URLs but content is served at clean URLs. Update sitemap
     to use clean URLs.
  7. Internal links (nav, footer, content) use .html URLs that get redirected.
     Update all internal links to use clean URLs directly to remove unnecessary
     307 redirects.
  8. Footer HTML structure issue: Three <a> tags inside one <li> under "Services"
     column. Should be three separate <li> elements.
  9. Footer has inconsistent "Emergency" column — present on newer pages
     (emergency-electrician, ev-charger-installation-los-angeles) but NOT on
     homepage or older pages. Need to propagate to all pages.
  10. Emergency service pages (emergency-electrician, etc.) missing
      Service/Electrician schema.

LOW (nice to fix):
  11. Copyright year shows "2025" — update to "2026".
  12. "TO ACTIVATE" placeholder comments present on all pages — remove for cleaner
      production HTML.
  13. Testimonials meta description is only 77 chars — extend for better SERP
      visibility.
  14. No <img> tags in visible page HTML — consider using <img> tags with alt
      text and loading="lazy" for better accessibility and Core Web Vitals.
